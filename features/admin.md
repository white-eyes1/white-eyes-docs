# 관리자 앱 기능 명세 (FNC-A-*)

> 원본: 명세서 시트 '기능 명세서(관리자)'에서 옮김. 이후로는 이 파일이 원본이다.


### FNC-A-001 최고 관리자 초기 등록

- **목적/설명**
  관리자 앱이 처음 켜질 때 최고 관리자 계정을 한 번 만든다
  목적: 첫 관리자 확보
  구현 위치: admin
- **사전 조건**: 관리자 앱 시작
- **입력 항목**: 환경변수 SUPER_ADMIN_LOGIN_ID, SUPER_ADMIN_INITIAL_PASSWORD
- **처리 순서**
  1. 시작 시 admin_account에 role=SUPER_ADMIN 계정이 있는지 확인
  2. 없으면 환경변수 값으로 생성: status=ACTIVE, must_change_password=1
- **업무 규칙/검증**: 이미 있으면 아무것도 안 함. 최고 관리자는 승인 취소·비활성화·탈퇴 불가
- **정상 결과**: 계정 1개 생성
- **예외 상황 및 처리**: 환경변수가 없으면 시작 실패(로그에 이유)
- **후속 동작**: 첫 로그인 때 비밀번호 변경 강제
- **관련 요구사항 ID**: perm-005
- **완료/검수 기준**: 재시작해도 두 번 만들지 않음

### FNC-A-002 사용자 목록

- **목적/설명**
  사용자 계정을 검색·필터·정렬해 페이지 단위로 본다
  목적: 사용자 관리
  구현 위치: admin
- **사전 조건**: 사용자 관리 화면(SCR-A-001)
- **입력 항목**: keyword(아이디·이름), status, 가입일 from~to, active(true/false), sort(createdAt/loginId/lastActiveAt, asc/desc), page, size
- **처리 순서**
  1. user_account 조회(조건 적용)
  2. 계정별 최근 활동 시각·활동 중 여부 계산(설정·규약 시트 '활동 중 판단')
  3. 페이지 응답
- **업무 규칙/검증**: 최근 활동 계산은 현재 페이지 계정들의 세션을 SPRING_SESSION_USER에서 한 번에 조회(계정마다 따로 조회하지 않음). active 필터·lastActiveAt 정렬은 세션 정보를 붙인 뒤 처리하므로 최대 1,000명 범위에서만 지원
- **정상 결과**: {items:[{id, loginId, name, email, phone, status, createdAt, lastActiveAt, active}], page...}
- **예외 상황 및 처리**: -
- **후속 동작**: -
- **관련 요구사항 ID**
  aclst-001
  aclst-003~004
- **완료/검수 기준**: 필터 조합·정렬·페이지 이동 확인

### FNC-A-005 사용자 비밀번호 재설정

  목적: 비밀번호 분실 대응
  구현 위치: admin
- **사전 조건**: 사용자 상세 창

- **정상 결과**: {temporaryPassword}
- **예외 상황 및 처리**: -
- **후속 동작**: 관리자가 사용자에게 직접 전달
- **관련 요구사항 ID**
  acman-001

### FNC-A-008 강제 로그아웃

- **목적/설명**
  접속 중인 사용자(관리자 이상) 또는 관리자(최고 관리자만)를 로그아웃시킨다
  목적: 부정 사용·장기 접속 차단
  구현 위치: admin
- **사전 조건**: 사용자·관리자 목록
- **입력 항목**: 대상 종류(경로: /users/{id} 또는 /admins/{id}), id
- **처리 순서**
  1. 사용자 대상은 관리자 이상, 관리자 대상은 최고 관리자만 허용
  2. 대상의 세션 모두 삭제(사용자는 SPRING_SESSION_USER, 관리자는 SPRING_SESSION_ADMIN에서 login_id로 찾음)

- **정상 결과**: 삭제한 세션 수 표시
- **예외 상황 및 처리**: 권한 부족: 403 / 세션 없음: 200(0건)
- **후속 동작**: -
- **관련 요구사항 ID**
  acman-007~008
  histwr-003
- **완료/검수 기준**: 대상 브라우저가 다음 요청에서 로그인 화면으로 이동

### FNC-A-012 행정구역 초기 적재

- **목적/설명**
  행정구역 경계 GeoJSON을 region에 넣고 중심점을 계산한다
  목적: 지도·합산의 기준 데이터 준비
  구현 위치: admin(1회 실행 작업)
- **사전 조건**: 읍·면·동 경계 GeoJSON 파일(서비스 대상 시·군·구만 자른 것). 지역마다 properties에 adm_cd(통계청 8자리 코드), adm_nm, sidonm(시·도 이름), sggnm(시·군·구 이름)이 있고 좌표는 WGS84. 파일 출처는 decisions/0014
- **입력 항목**: 관리자 앱 실행 옵션 --job=load-regions --file={경계 파일}
- **처리 순서**
  1. 읍·면·동 코드의 앞 5자리로 시·군·구, 앞 2자리로 시·도 행을 만든다(이름은 sggnm·sidonm, 경계는 소속 읍·면·동 경계를 JTS로 합침)
  2. 시·도 → 시·군·구 → 읍·면·동 순으로 parent_id 연결
  3. 각 경계의 내부 점(JTS getInteriorPoint)을 center_lat/lng로 저장
  4. code 기준으로 덮어씀(다시 실행해도 중복 없음)
- **업무 규칙/검증**: 읍·면·동 이름은 adm_nm의 마지막 단어. 파일에 시·도·시·군·구 다각형은 없어도 됨
- **정상 결과**: region 행 생성·갱신
- **예외 상황 및 처리**: 파일 형식 오류: 작업 중단, 아무것도 저장하지 않음(트랜잭션)
- **후속 동작**: -
- **관련 요구사항 ID**: loca-001
- **완료/검수 기준**: 다시 실행해도 중복이 없고, 시·도/시·군·구/읍·면·동의 상위 연결이 원본 코드와 맞으며, 상위 지역 행이 파일에 없어도 만들어짐

### FNC-A-013 구역 미리보기 계산

- **목적/설명**
  그린 다각형의 면적·소속 동을 저장 전에 계산해 보여준다
  목적: 등록 전 확인
  구현 위치: admin
- **사전 조건**: 구역 관리 화면에서 다각형 그림
- **입력 항목**: boundary(GeoJSON Polygon)
- **처리 순서**
  1. 다각형 검증(점 3개 이상, 자기 교차 없음 — JTS isValid)
  2. 내부 점이 들어가는 읍·면·동(EMD) 찾기
  3. 면적 계산: 내부 점의 위도 φ0 기준으로 x=경도×111,320×cos φ0, y=위도×110,540(m)로 바꾼 뒤 평면 면적
  4. {areaM2, dongId, dongName} 반환
- **업무 규칙/검증**: 수백 m 크기 구역에서 오차 1% 미만
- **정상 결과**: 면적·소속 동 표시
- **예외 상황 및 처리**: 잘못된 다각형: 400 INVALID_POLYGON / 서비스 지역 밖: 400 OUT_OF_SERVICE_AREA
- **후속 동작**: -
- **관련 요구사항 ID**: loca-003
- **완료/검수 기준**: 알려진 크기의 사각형으로 면적 확인

### FNC-A-043 다시보기 녹화 찾기

- **목적/설명**
  구역·시각으로 녹화와 재생 시작 위치를 찾는다
  목적: 그래프·이벤트에서 영상으로 연결

  2. 구역의 캠(삭제 포함) 녹화 중 started_at ≤ at 이고 (ended_at > at 또는 ended_at IS NULL) 인 것 중 started_at이 가장 늦은 것
  3. 없으면 404 RECORDING_NOT_FOUND('영상 없음')

  [latest=true]

  [구간 조회 GET /api/v1/playback/ranges]
  6. from ≥ to이거나 to−from이 24시간을 넘으면 400 INVALID_INPUT
  7. 구역의 캠(삭제 포함) 녹화 중 started_at < to 이고 (ended_at > from 또는 ended_at IS NULL) 인 것을 조회(RECORDING_RETENTION_DAYS(기본 30일)를 넘은 부분은 제외)

- **정상 결과**: 재생 정보(구간 조회는 녹화 구간 목록)

- **완료/검수 기준**: 라이브 최근 1~2분은 '영상 없음'

### FNC-A-051 시연용 통계 생성

- **목적/설명**
  규칙 기반으로 과거 1년 치 시간별·일별 통계를 만든다
  목적: 장기 통계 시연
  구현 위치: admin(1회 실행 작업)
- **사전 조건**: 구역·이웃 등록 완료
- **입력 항목**: 실행 옵션: --job=generate-demo --config={설정 파일}. 설정: seed, 시작일, 구역별 기본 인원·평균 체류(초), 패턴 가중치, 특정일 급증 날짜 목록
- **처리 순서**
  1. 구역마다 종료일 = 그 구역 캠의 first_started_at 전날(없으면 어제)
  2. 시간마다 인원 = 기본 인원 × 시간대 가중치 × 요일 가중치 × 계절 가중치 × 특정일 가중치 × 무작위(±10%, seed 고정)
  3. 이동량: 이웃 쌍마다 이동 인원을 만들고 A의 d 방향 유출 = B의 반대 방향 유입으로 맞춤. 이웃 없는 방향은 바깥과 주고받는 인원을 따로 만듦
  4. count_max = avg×1.3, count_min = avg×0.7, density = avg÷면적, dwell_count = 유출 합, dwell_sum_sec = dwell_count × 평균 체류(±20%), sample_sec = 3600, is_demo = 1
  5. 시간별 저장 후 같은 규칙으로 일별 저장(일별 is_demo=1)
- **업무 규칙/검증**: 같은 seed면 같은 결과. 1분 통계는 만들지 않음. 기존 시연 데이터가 있으면 먼저 지우고 다시 만듦
- **정상 결과**: 시간별·일별 시연 데이터
- **예외 상황 및 처리**: -
- **후속 동작**: -
- **관련 요구사항 ID**: demo-001
- **완료/검수 기준**: 일별 = 시간별 합과 일치
