# 공용 기능 명세 (FNC-C-*)

> 원본: 명세서 시트 '공용 기능 명세서'에서 옮김. 이후로는 이 파일이 원본이다.


### FNC-C-001 로그인

- **목적/설명**
  아이디·비밀번호로 로그인한다. 앱마다 로그인할 수 있는 권한이 다르다
  목적: 앱별 로그인 처리(Spring Security 폼 로그인)
  구현 위치: common(두 앱)
- **사전 조건**: 로그인 화면(SCR-C-001) 진입
- **입력 항목**: 아이디, 비밀번호
- **처리 순서**
  1. 아이디로 계정 조회(사용자 앱: user_account, 관리자 앱: admin_account)
  2. bcrypt로 비밀번호 비교
  3. 상태 확인(아래 규칙)
  4. 권한 부여(사용자 앱: ROLE_USER, PENDING이면 ROLE_PENDING / 관리자 앱: admin_account.role)
  5. 세션 생성(쿠키 USER_SESSION / ADMIN_SESSION), 그 계정 테이블의 last_login_at 갱신
  6. 이동: PENDING이면 승인 대기 화면, must_change_password=1이면 비밀번호 변경 화면, 그 외 통계 메인
- **업무 규칙/검증**
  · ACTIVE: 정상 로그인
  · PENDING: 사용자 앱에서만 로그인 허용, 권한은 승인 대기 화면만(ROLE_PENDING)
  · DISABLED·WITHDRAWN: 로그인 거부
  · 다른 앱의 계정: 이 앱의 계정 테이블에 없으므로 '아이디 없음'과 같이 거부
  · 거부 사유와 관계없이 화면 문구는 '아이디 또는 비밀번호가 올바르지 않습니다.' 하나로 통일(계정 존재 여부를 드러내지 않음). 단 DISABLED는 '사용이 중지된 계정입니다.'
- **정상 결과**: 세션 생성 후 다음 화면으로 이동
- **예외 상황 및 처리**: 실패 시 로그인 화면에 오류 문구 표시, 입력한 아이디는 유지
- **후속 동작**: 로그인 시도 횟수 제한은 2순위(2순위 기능 시트)
- **관련 요구사항 ID**
  auth-002
  perm-001~005
- **완료/검수 기준**
  · 각 상태·역할 조합별 허용/거부 확인
  · 두 앱에 동시에 로그인해도 서로 세션이 덮어써지지 않음

- **입력 항목**: -

  2. 세션 삭제
  3. 로그인 화면으로 이동
- **업무 규칙/검증**: -

- **예외 상황 및 처리**: 세션이 이미 없으면 그대로 로그인 화면으로 이동
- **후속 동작**: -

### FNC-C-003 접근 권한 검사

- **목적/설명**
  요청 경로마다 필요한 권한을 확인한다
  목적: 화면·API 접근 통제
  구현 위치: common(두 앱)
- **사전 조건**: 모든 요청
- **입력 항목**: 요청 경로, 세션의 권한
- **처리 순서**
  1. 공개 경로(로그인·회원가입·정적 파일) 통과
  2. 세션 없음 → 화면은 로그인 화면으로, API는 401
  3. 경로별 필요 권한 비교 → 부족하면 403
  4. must_change_password=1이면 비밀번호 변경 화면·API·로그아웃 외에는 비밀번호 변경 화면으로 보냄
- **업무 규칙/검증**
  권한 표(사용자 앱)
  - 공개: /login, /signup, /api/v1/signup/**
  - PENDING: /pending, /logout
  - USER: 그 외 전부
  권한 표(관리자 앱)
  - 공개: /admin/login
  - ADMIN 이상: 그 외 전부
  - SUPER_ADMIN만: /admin/admins/**, /admin/api/v1/admins/**, /admin/histories/**, /admin/api/v1/histories/**
  - /internal/** 은 8082 포트에서 X-Internal-Token으로만 인증(세션 사용 안 함)
- **정상 결과**: 요청 처리
- **예외 상황 및 처리**: 401/403은 공통 오류 응답 형식(설정·규약 시트)
- **후속 동작**: -
- **관련 요구사항 ID**
  perm-001~005
  sec-004
- **완료/검수 기준**: 권한 표의 각 경로를 역할별로 호출해 허용/거부 확인

### FNC-C-004 세션 만료·정리

- **목적/설명**
  일정 시간 동작이 없으면 세션을 끝내고, 만료 세션을 주기적으로 지운다
  목적: 자동 로그아웃과 세션 테이블 관리
  구현 위치: common 설정(두 앱 모두 정리 작업 켬)
- **사전 조건**: -
- **입력 항목**: -
- **처리 순서**
  1. 마지막 요청 후 30분이 지나면 세션 만료
  2. 각 앱이 10분마다 자기 세션 테이블의 만료 세션을 삭제(Spring Session 정리 작업)
- **업무 규칙/검증**: 정리 작업은 두 앱 모두 켜고 각자 자기 세션 테이블만 정리. 같은 앱이 여러 대여도 같은 만료 행을 지우는 작업이라 중복 실행해도 문제없음
- **정상 결과**: 만료된 세션으로 요청하면 로그인 화면으로 이동
- **예외 상황 및 처리**: -
- **후속 동작**: -
- **관련 요구사항 ID**: sec-003
- **완료/검수 기준**: 30분 무동작 후 요청 시 로그인 화면으로 이동, 만료 세션 행이 정리됨

### FNC-C-005 비밀번호 암호화

- **목적/설명**
  비밀번호를 bcrypt로 저장·비교한다
  목적: 비밀번호 보호
  구현 위치: common
- **사전 조건**: -
- **입력 항목**: 평문 비밀번호
- **처리 순서**
  1. 저장 시 BCryptPasswordEncoder(강도 10)로 변환해 계정 테이블(user_account·admin_account)의 password에 저장
  2. 로그인·현재 비밀번호 확인 시 matches로 비교
- **업무 규칙/검증**: 평문은 로그·작업 기록·응답 어디에도 남기지 않음
- **정상 결과**: 60자 bcrypt 문자열 저장
- **예외 상황 및 처리**: -
- **후속 동작**: -
- **관련 요구사항 ID**: sec-001
- **완료/검수 기준**: DB에 평문이 없음, 같은 비밀번호도 저장값이 매번 다름

### FNC-C-006 내 정보 조회·수정

- **목적/설명**
  로그인한 회원이 자신의 이름·메일·연락처를 바꾼다
  목적: 본인 정보 관리
  구현 위치: common(두 앱)
- **사전 조건**: 로그인, 내 정보 화면(SCR-C-002)
- **입력 항목**: 이름, 메일(선택), 연락처(선택)
- **처리 순서**
  1. GET /api/v1/me 로 현재 정보 표시
  2. 수정 후 PATCH /api/v1/me
  3. 입력값 검증 후 저장
  4. 작업 기록(ACCOUNT_CHANGE, 대상 본인 계정, detail: 바뀐 필드 이전·이후 값. 바뀐 값이 없으면 기록하지 않음)
- **업무 규칙/검증**: 입력값 규칙은 설정·규약 시트. 아이디·역할·상태는 바꿀 수 없음
- **정상 결과**: 저장 완료 안내
- **예외 상황 및 처리**: 검증 실패 시 필드별 오류 표시(400)
- **후속 동작**: -
- **관련 요구사항 ID**
  auth-004
  histwr-003
- **완료/검수 기준**: 각 필드 경계값 검증, 저장 후 다시 조회 시 반영

### FNC-C-007 비밀번호 변경

- **목적/설명**
  현재 비밀번호를 확인하고 새 비밀번호로 바꾼다. 임시 비밀번호로 로그인한 경우 강제로 이 화면을 거친다
  목적: 비밀번호 변경·첫 로그인 강제 변경
  구현 위치: common(두 앱)
- **사전 조건**: 로그인
- **입력 항목**: 현재 비밀번호, 새 비밀번호, 새 비밀번호 확인
- **처리 순서**
  1. 현재 비밀번호 확인
  2. 새 비밀번호 규칙·확인 일치 검사
  3. 저장, must_change_password=0
  4. 이 계정의 다른 세션은 모두 삭제(현재 세션은 유지)
- **업무 규칙/검증**: 새 비밀번호는 현재 비밀번호와 달라야 함
- **정상 결과**: 변경 완료 후 통계 메인으로 이동
- **예외 상황 및 처리**: 현재 비밀번호 불일치: 400 WRONG_PASSWORD / 규칙 위반: 400 필드 오류
- **후속 동작**: -
- **관련 요구사항 ID**
  auth-004
  acman-009
- **완료/검수 기준**: 첫 로그인 강제 변경, 다른 브라우저 세션이 끊기는지 확인

### FNC-C-008 지역·구역 목록

- **목적/설명**
  시 → 구 → 동 → 구역 순으로 하위 목록과 경계를 내려준다
  목적: 지도 탐색용 지역 트리 제공
  구현 위치: common(두 앱)
- **사전 조건**: 통계 메인 화면
- **입력 항목**: parentId(없으면 시·도 목록) 또는 dongId(구역 목록, 생략하면 전체 구역)
- **처리 순서**
  1. parentId가 없으면 level=SIDO 목록
  2. parentId가 있으면 그 하위 region 목록
  3. 구역 목록: dongId가 있으면 그 동의, 없으면 전체의 삭제되지 않은 구역(zone.deleted_at IS NULL)
  4. 경계(GeoJSON)와 중심점 함께 반환
- **업무 규칙/검증**: 삭제된 구역은 지도·목록에서 제외(loca-005). 다만 구역 번호로 하나를 조회하는 `GET /api/v1/zones/{id}`는 삭제된 구역도 `deleted: true`로 준다(지난 통계·다시보기가 '(삭제됨)'을 붙이는 데 씀)
- **정상 결과**: 하위 목록 반환
- **예외 상황 및 처리**: 없는 지역: 404 REGION_NOT_FOUND. 단건 조회에서 없는 구역: 404 ZONE_NOT_FOUND
- **후속 동작**: 지도 화면이 경계를 그리고 FNC-C-009로 색을 칠함
- **관련 요구사항 ID**
  map-001
  loca-001
- **완료/검수 기준**: 시~구역까지 내려가며 목록·경계가 맞는지 확인

### FNC-C-009 혼잡 단계 색 표시

- **목적/설명**
  선택한 지역의 하위 단위를 최근 1분 통계의 혼잡 단계 색으로 칠한다
  목적: 현재 혼잡 상태를 지도에서 보여줌
  구현 위치: common(두 앱)
- **사전 조건**: 통계 메인 화면
- **입력 항목**: regionId, unit(CHILD / ZONE)
- **처리 순서**
  1. 단위 목록 조회: CHILD면 바로 아래 단위(동이면 구역), ZONE이면 대상 아래 모든 구역(중심점 포함)
  2. 각 단위의 가장 최근 1분 통계(최근 5분 이내)를 조회
  3. 지역은 소속 구역 값을 합산(설정·규약 시트 '혼잡 단계 판정')
  4. 단계·색 계산
  5. 단위별 오늘 혼잡·급증 이벤트 수와 진행 중 이벤트 여부를 붙여 반환
- **업무 규칙/검증**: 최근 5분 안에 통계가 없으면 '데이터 없음'(회색)
- **정상 결과**: 단위별 {id, name, countAvg, density, level, statAt, todayEventCount, ongoingEvent} (+ ZONE이면 centerLat, centerLng)
- **예외 상황 및 처리**: -
- **후속 동작**: 실시간 갱신(FNC-C-022)으로 1분마다 다시 칠함
- **관련 요구사항 ID**
  map-003
  evthres-001~002
- **완료/검수 기준**: 단계 경계값 바로 아래·위에서 색이 바뀌는지 확인

### FNC-C-010 구역 간 이동 흐름

- **목적/설명**
  선택한 기간의 구역 간 이동량을 화살표로 보여준다
  목적: 이동 흐름 시각화
  구현 위치: common(두 앱)
- **사전 조건**: 통계 메인 화면
- **입력 항목**: regionId, from, to
- **처리 순서**
  1. 지역 안 구역 목록과 이웃 정보(zone_neighbor) 조회
  2. 기간의 방향별 유출 합계 조회(1일 이상 걸친 구간은 일별, 나머지는 시간별, 1시간 미만은 1분 통계)
  3. 구역 A의 방향 d 유출 = A의 d 방향 이웃 B로 간 인원. 이웃이 없으면 '관측 범위 밖'
  4. {fromZoneId, toZoneId(null=관측 범위 밖), direction, count} 반환
- **업무 규칙/검증**: 현재 이웃 설정으로 계산(알려진 한계 14). count 0인 화살표는 보내지 않음
- **정상 결과**: 이동 목록 반환. 화면은 화살표 굵기를 count 비율로 그림
- **예외 상황 및 처리**: 기간 오류(to ≤ from): 400 INVALID_RANGE / 시각 형식 오류: 400 INVALID_INPUT / 없는 지역: 404 REGION_NOT_FOUND
- **후속 동작**: -
- **관련 요구사항 ID**
  stats-006
  map-002
- **완료/검수 기준**: 이웃이 있는/없는 방향 모두 확인, 반대 방향 화살표가 따로 그려지는지 확인

### FNC-C-011 시간대별 히트맵

- **목적/설명**
  기간·항목을 골라 하위 단위를 시간대(0~23시)별 평균값으로 칠한다
  목적: 시간대에 따른 활성도 변화 확인
  구현 위치: common(두 앱)
- **사전 조건**: 통계 메인 화면에서 히트맵 켬
- **입력 항목**: regionId, from, to, item(COUNT/DENSITY/INFLOW/OUTFLOW), dayType(ALL/WEEKDAY/WEEKEND)
- **처리 순서**
  1. 시간별 통계에서 기간·요일 조건에 맞는 행 조회

### FNC-C-020 기간 비교 분석

- **목적/설명**

  목적: 평시 대비 변화 확인
  구현 위치: common(두 앱)
- **사전 조건**: 기간 비교 화면
- **입력 항목**: targetType, targetId, 대상 기간(from,to), 기준 기간(from,to 또는 프리셋: LAST_MONTH/LAST_YEAR), 기준 %(기본 30)
- **처리 순서**
  1. 두 기간의 시간별 통계 조회(지역은 합산)
  2. (요일 7 × 시간 24) 칸마다 대상 평균·기준 평균 계산

  4. 전체 평균 증감률도 계산: 비교 가능한 칸만 모아 (대상 평균들의 평균 − 기준 평균들의 평균) ÷ 기준 평균들의 평균 × 100. 비교 가능한 칸이 없으면 totalRate는 null
- **업무 규칙/검증**: 기간은 각각 최대 1년. 기준 평균이 0이거나 없는 칸은 비교 불가(회색). 프리셋: 지난달=대상 기간을 28일 앞으로, 지난해 같은 기간=364일 앞으로
- **정상 결과**: {cells:[{weekday, hour, targetAvg, baseAvg, rate, abnormal}], totalRate}
- **예외 상황 및 처리**: 기간 오류: 400
- **후속 동작**: -
- **관련 요구사항 ID**: cmp-001~003
- **완료/검수 기준**: 비정상 칸 판정 경계(±기준%) 확인

### FNC-C-023 통계 엑셀 다운로드

- **처리 순서**
  1. 단위별 최대 기간·예상 행 수(구역 수×점 수) 확인
