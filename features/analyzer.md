# 분석 서버·운영 기능 명세 (FNC-S-*)

> 원본: 명세서 시트 '기능 명세서(분석 서버·운영)'에서 옮김. 이후로는 이 파일이 원본이다.


### FNC-S-001 캠 시작

- **목적/설명**
  관리자 앱의 시작 지시를 받아 캠 작업(스레드)을 띄운다
  목적: 분석 시작
  구현 위치: analyzer
- **사전 조건**: X-Internal-Token 일치
- **입력 항목**: cameraId(경로), sourceType·sourceUri(본문)
- **처리 순서**
  1. 이미 그 캠 작업이 돌고 있으면 현재 상태 그대로 응답(중복 시작 없음)
  2. LIVE: 라이브 작업(FNC-S-007) 시작, 응답 status=RUNNING
  3. DUMMY: 캐시(FNC-S-009)가 있으면 재생 작업(FNC-S-010) 시작 → RUNNING / 없으면 준비 작업 시작 → PREPARING
  4. 200 {status}
- **업무 규칙/검증**: 캠 작업은 캠마다 스레드 1개 + 정지 플래그. 동시 탐지는 모델 1개를 잠금으로 공유(CPU 1대 기준). 이미 돌고 있는지 확인은 요청 내용(sourceType·sourceUri)보다 먼저 하고, DUMMY 경로는 MEDIA_ROOT 안의 파일만 허용
- **정상 결과**: 200 {cameraId, status}
- **예외 상황 및 처리**: 파일 없음(DUMMY): 400 SOURCE_NOT_FOUND → 관리자 앱이 ERROR로 저장 / 본문 형식 오류: 400 INVALID_REQUEST / LIVE(2단계 구현 전): 501 SOURCE_TYPE_NOT_SUPPORTED / 토큰 불일치: 401
- **후속 동작**: 이후 상태 변화는 상태 보고(PATCH /internal/v1/cameras/{id}/status)
- **관련 요구사항 ID**
  caman-003
  vanly-005
- **완료/검수 기준**: 같은 시작을 두 번 보내도 작업이 하나

### FNC-S-002 캠 정지

- **목적/설명**
  캠 작업을 멈추고 진행 중인 녹화를 마무리한다
  목적: 분석 중지
  구현 위치: analyzer
- **사전 조건**: X-Internal-Token 일치
- **입력 항목**: cameraId
- **처리 순서**
  1. 정지 플래그 설정, 작업 종료를 최대 10초 기다림
  2. LIVE: 녹화 중이던 파일을 닫아 공유 폴더로 옮기고 등록(FNC-S-008 4~6번, 1분 미만 파일도 등록)
  3. 준비 중(DUMMY)이면 준비 취소, 만들던 캐시 임시 파일 삭제
  4. 전송 대기 중인 결과는 그대로 둠(전송 작업이 보냄)
  5. 200
- **업무 규칙/검증**: 작업이 없어도 200(멱등)
- **정상 결과**: 200
- **예외 상황 및 처리**: -
- **후속 동작**: -
- **관련 요구사항 ID**: caman-003
- **완료/검수 기준**: 정지 후 같은 캠 MJPEG 요청은 404

### FNC-S-003 사람 탐지·추적

- **목적/설명**
  프레임마다 사람을 찾고 추적 번호를 붙인다
  목적: 인원 계산·이동 판정의 기본 데이터
  구현 위치: analyzer
- **사전 조건**: 캠 작업 실행 중
- **입력 항목**: 영상 프레임(초당 ANALYZE_FPS개로 솎음)
- **처리 순서**
  1. 탐지: YOLO-CROWD(YOLO_WEIGHTS)를 YOLOv5 저장소 코드로 불러와 프레임을 DETECT_IMGSZ 크기로 맞춰(letterbox) 추론하고, conf=DETECT_CONF, IoU 0.45로 겹친 박스를 제거(non_max_suppression). CPU 추론. 클래스가 'people' 하나라 클래스 필터가 필요 없음
  2. 추적: 탐지 박스를 ByteTrack(Ultralytics의 BYTETracker)에 넣어 추적 번호를 붙임. YOLO-CROWD는 ultralytics의 model.track()으로 불러올 수 없어서 탐지와 추적을 따로 호출
  3. 결과: 추적 번호, 박스(x, y, w, h — 영상 크기 대비 0~1 비율), 중심점
  4. 인원 = 그 프레임의 박스 수(추정 인원. 센 수는 실제의 일부, 알려진 한계 16)
  5. 추적기 상태는 캠마다 BYTETracker 인스턴스를 따로 둠(탐지 모델은 하나를 잠금으로 공유)
- **업무 규칙/검증**: 추적 번호가 없는 박스(추적 시작 전)는 인원에는 넣고 이동 판정에서는 뺌. 박스는 사람 머리라 작다(입력 960에서 약 8px). 프레임 사이 박스 겹침이 작아 추적 번호가 자주 바뀔 수 있으므로 추적 정확도는 실제 영상으로 확인
- **정상 결과**: 프레임별 [추적 번호, 박스] 목록
- **예외 상황 및 처리**: 탐지 오류 프레임은 건너뜀(로그)
- **후속 동작**: FNC-S-004·005, 좌표 파일 기록
- **관련 요구사항 ID**: vanly-001
- **완료/검수 기준**
  · VisDrone 사진 120장 기준 센 수와 실제 수의 상관계수 0.7 이상(YOLO-CROWD, 입력 960: 0.70)
  · 실제 더미 영상 몇 개에서 사람이 센 값과 비교해 오차(상관계수, 실제 대비 비율)를 기록
  · 머리 박스에서 추적 번호가 유지되는지 샘플 영상으로 확인

### FNC-S-004 유입/유출 판정

- **목적/설명**
  추적 중인 사람이 화면 변 안쪽 판정선을 넘으면 방향별 유입/유출로 센다
  목적: 구역 간 이동량 계산
  구현 위치: analyzer
- **사전 조건**: FNC-S-003 결과
- **입력 항목**: 추적 번호별 직전·현재 중심점
- **처리 순서**
  1. 판정선: 각 변에서 안쪽으로 EDGE_MARGIN_RATIO(5%) 위치. 바깥 띠 = 북(y<0.05)·남(y>0.95)·서(x<0.05)·동(x>0.95)
  2. 사람마다 상태 기억: 처음 본 위치가 바깥 띠 d면 entry=d, 안쪽이면 entry=없음(화면 안에서 생김)
  3. 바깥 띠 d → 안쪽으로 들어오면 in[d] += 1 (entry가 d일 때)
  4. 안쪽 → 바깥 띠 d로 나가면 그 사람을 '나가는 중(d)'으로 표시
  5. 추적이 끊기고 1초(ANALYZE_FPS 프레임) 동안 다시 안 나타나면 확정: 마지막 상태가 '나가는 중(d)'이면 out[d] += 1, 아니면 세지 않음(화면 안에서 사라짐)
  6. 모서리(두 띠가 겹침)는 띠 깊이가 더 깊은 쪽 방향
- **업무 규칙/검증**: 방향은 화면 위=북 가정(알려진 한계 15). 화면 안에서 생기거나 사라지는 사람은 제외(알려진 한계 1)
- **정상 결과**: 초 단위 in{N,E,S,W}, out{N,E,S,W}
- **예외 상황 및 처리**: -
- **후속 동작**: 1초 결과에 담김
- **관련 요구사항 ID**
  vanly-002
  stats-005~006
- **완료/검수 기준**: 판정선을 지나가는 사람 영상으로 방향별 수 확인

### FNC-S-006 1초 결과 전송·재전송

- **목적/설명**
  캠별 1초 결과를 모아 관리자 앱으로 보내고 실패분은 5분까지 다시 보낸다
  목적: 통계 원천 전달
  구현 위치: analyzer
- **사전 조건**: 캠 작업 실행 중
- **입력 항목**: 캠별 1초 결과 {cameraId, at, personCount, in, out, dwellSec[]}
- **처리 순서**
  1. 캠 작업이 매 초(벽시계 초 경계)마다 결과를 전송 큐에 넣음. personCount = 그 1초 프레임들의 인원 평균(반올림), in/out·dwellSec = 그 1초 동안의 합·목록
  2. 전송 스레드가 1초마다 큐 전체를 POST /internal/v1/results 로 한 번에 보냄(타임아웃 3초)
  3. 실패(연결 실패·5xx): 보관 버퍼에 남김. 버퍼에서 at이 현재−RESULT_RETRY_BUFFER_SEC보다 오래된 것은 버림
  4. 다음 전송 때 버퍼 + 새 결과를 함께 보냄(최대 2,000건씩)
  5. 4xx(형식 오류): 그 묶음 버림, 로그
- **업무 규칙/검증**: at = 그 1초 구간의 시작(초 단위, KST). 더미 캠은 영상 시각이 아니라 실제 재생되는 현재 시각을 at으로 씀
- **정상 결과**: 관리자 앱 204
- **예외 상황 및 처리**: 관리자 앱이 5분 넘게 꺼져 있으면 그 사이 결과는 사라짐(빈 구간)
- **후속 동작**: -
- **관련 요구사항 ID**: vanly-006
- **완료/검수 기준**: 관리자 앱을 2분 껐다 켜면 그 사이 1분 통계가 채워짐

### FNC-S-007 라이브 분석·재연결

- **목적/설명**
  RTSP 스트림을 읽어 분석·녹화하고, 끊기면 다시 연결한다
  목적: 실시간 캠 처리
  구현 위치: analyzer
- **사전 조건**: 캠 시작(LIVE)
- **입력 항목**: sourceUri(rtsp://)
- **처리 순서**
  1. OpenCV(FFmpeg 백엔드) VideoCapture로 연결
  2. 읽은 프레임은 모두 녹화기(FNC-S-008)로, ANALYZE_FPS에 맞춰 솎은 프레임만 분석(FNC-S-003~005)
  3. 최신 분석 프레임 + 박스를 MJPEG·스냅샷용 버퍼에 저장(FNC-S-011)
  4. 읽기 실패: 2초 간격으로 다시 연결. LIVE_RECONNECT_FAIL_SEC(30초) 넘게 실패하면 상태 보고 ERROR(errorMessage='스트림 연결 실패')
  5. ERROR 뒤에도 30초 간격으로 계속 다시 연결 시도, 성공하면 RUNNING 보고
- **업무 규칙/검증**: 분석이 프레임 속도를 못 따라가면 오래된 프레임을 버리고 최신 프레임 기준으로 분석(지연 누적 방지)
- **정상 결과**: 분석 결과·녹화·실시간 화면 생성
- **예외 상황 및 처리**: -
- **후속 동작**: -
- **관련 요구사항 ID**
  vanly-001
  vanly-007
  evtdet-003
- **완료/검수 기준**: 스트림을 끊었다 30초 뒤 ERROR, 다시 연결하면 RUNNING

### FNC-S-008 라이브 녹화(1분 파일)

- **목적/설명**
  원본 영상을 시계 분 단위 파일로 녹화하고 좌표 파일과 함께 등록한다
  목적: 다시보기 원본 확보
  구현 위치: analyzer
- **사전 조건**: 라이브 작업 실행 중
- **입력 항목**: 원본 프레임, 프레임별 박스
- **처리 순서**
  1. 녹화용 ffmpeg 프로세스에 프레임을 파이프로 넘김: RECORD_WIDTH×RECORD_HEIGHT, RECORD_FPS로 변환, libx264, -f segment -segment_time 60 -segment_atclocktime 1 -reset_timestamps 1 -segment_format_options movflags=+faststart, 파일은 /var/lib/analyzer/tmp/ 에
  2. 분석 프레임마다 좌표 [t, 박스 목록]을 지금 분 파일용 목록에 추가(t = 그 분 파일 시작부터의 초)
  3. 분이 바뀌면(파일 완성) 좌표 목록을 .json.gz로 저장
  4. 영상·좌표 파일을 공유 폴더 recordings/live/cam{id}/{yyyyMMdd}/ 로 옮김(같은 이름, 확장자만 다름)
  5. POST /internal/v1/recordings {cameraId, startedAt, endedAt, videoPath, boxPath}
  6. 등록 실패: 1분 간격 재시도(최대 10번), 계속 실패하면 로그(파일은 남음)
- **업무 규칙/검증**: 파일 이름 시각 = 그 분의 시작(cam{id}_{yyyyMMdd_HHmm}). 첫 파일은 가동 시각부터 다음 분까지라 1분보다 짧음. 좌표 파일 형식은 설정·규약 시트
- **정상 결과**: 공유 폴더에 1분 파일 2개, recording 1행
- **예외 상황 및 처리**: 공유 폴더 쓰기 실패: 로컬에 남기고 다음 분에 다시 옮김
- **후속 동작**: -
- **관련 요구사항 ID**
  rec-001
  rec-004
- **완료/검수 기준**: 브라우저에서 구간 이동 재생이 되는지(faststart) 확인

### FNC-S-009 더미 분석 준비

- **목적/설명**
  더미 영상을 한 번 끝까지 분석해 결과 캐시와 좌표 파일을 만든다
  목적: 반복 재생 때 다시 분석하지 않음
  구현 위치: analyzer
- **사전 조건**: 캠 시작(DUMMY), 캐시 없음
- **입력 항목**: sourceUri(dummy/videos/…mp4)
- **처리 순서**
  1. 상태 보고 PREPARING, progress=0
  2. 영상을 ANALYZE_FPS로 처음부터 끝까지 분석(FNC-S-003~005, 추적기 새로 시작)
  3. 영상 시각 기준 초별 결과 {sec, personCount, in, out, dwellSec[]}를 캐시 파일(/var/lib/analyzer/cache/{파일명}.json)로 저장
  4. 프레임별 박스를 좌표 파일 dummy/boxes/{파일명}.json.gz 로 내보냄(t = 영상 시작부터의 초)
  5. 진행률: 5% 오를 때마다 상태 보고(progress)
  6. 완료 → 재생 작업(FNC-S-010) 시작, 상태 보고 RUNNING
- **업무 규칙/검증**: 캐시·좌표 파일은 영상 파일 이름 기준이라 같은 영상을 쓰는 캠끼리 공유. 다른 캠이 같은 영상을 준비 중이면 끝날 때까지 기다림(파일 잠금). 영상 파일을 바꿀 땐 파일 이름도 바꿔야 함
- **정상 결과**: 캐시·좌표 파일 생성

### FNC-S-010 더미 재생·반복 등록

- **목적/설명**

  목적: 실시간처럼 보이는 더미 캠
  구현 위치: analyzer
- **사전 조건**: 캐시 있음
- **입력 항목**: 캐시, 영상 길이 L초
- **처리 순서**

  5. 실시간 화면·카드 미리보기용: 영상을 같은 위치로 읽어 박스를 그려 MJPEG·스냅샷용 버퍼에 저장(MJPEG 시청자가 있거나 최근 10초 안에 스냅샷 요청이 있을 때만)

### FNC-S-011 MJPEG 스트림·카드 미리보기

- **목적/설명**
  가동 중인 캠의 최신 프레임에 박스를 그려 MJPEG(실시간 화면) 또는 JPEG 1장(카드 미리보기)으로 보낸다
  목적: 관리자 실시간 화면·캠 카드 미리보기
  구현 위치: analyzer
- **사전 조건**: nginx 권한 확인 통과, X-Internal-Token 일치
- **입력 항목**: cameraId
- **처리 순서**
  [MJPEG /live]
  1. 캠 작업이 없으면 404
  2. 응답 Content-Type: multipart/x-mixed-replace; boundary=frame
  3. 초당 최대 ANALYZE_FPS번: 최신 프레임에 박스(초록 사각형)·인원수 글자를 그려 JPEG(품질 70, 가로 960px)로 보냄
  4. 시청자 수를 세어, 0명이면 프레임 그리기·JPEG 변환을 멈춤
  [스냅샷 /snapshot]
  5. 캠 작업이 없으면 404
  6. 최신 프레임에 박스·인원수를 그려 JPEG(품질 60, 가로 320px) 1장 응답, Cache-Control: no-store
  7. 같은 캠의 스냅샷은 1초 동안 재사용(여러 관리자·카드가 동시에 요청해도 한 번만 변환)
- **업무 규칙/검증**: 분석과 별개로 그리기만 함(분석 속도에 영향 최소화). 스냅샷은 요청이 있을 때만 만듦(보는 사람이 없으면 부하 없음)
- **정상 결과**: MJPEG 스트림 / JPEG 1장
- **예외 상황 및 처리**: 클라이언트가 끊으면 생성기 종료
- **후속 동작**: -

  live-001~002
  sec-004
- **완료/검수 기준**: 창을 닫으면 시청자 수가 줄어듦. 1초 안에 같은 캠 스냅샷을 두 번 요청하면 같은 이미지
