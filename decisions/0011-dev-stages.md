# 0011. 1순위 기능을 개발 단계 1·2·3단계로 나눔

- 상태: 채택
- 기록: 2026-10-19
- 관련: features/index.md, GitHub 보드 `pjt-white-eyes-develop`(white-eyes1 조직 프로젝트 2)의 `단계` 필드, white-eyes-spring·white-eyes-flask 이슈

## 결정
features/index.md의 1순위 기능 97개를 구현 순서로 세 단계로 나눈다. 우선순위(상·중·하)는 그대로 두고, 단계는 보드의 `단계` 필드와 이 기록으로 관리한다.

| 단계 | 기준 | 개수 |
|---|---|---|
| 1단계 | 로그인 → 구역·캠 등록 → 캠 가동 → 더미 영상 분석 → 1초 결과 전송 → 1분 통계 저장 → 지도·대시보드 표시 → 정지가 끝까지 도는 최소 기능 | 29 |
| 2단계 | 1단계에 들지 않은 우선순위 '상' | 35 |
| 3단계 | 1단계에 들지 않은 우선순위 '중'·'하' | 33 |

1단계 기능
- white-eyes-spring: FNC-C-001·003·005·008·009·016·025·026·027, FNC-A-001·012·013·014·018·020·021·022·024·025·026·028
- white-eyes-flask: FNC-S-001·002·003·004·005·006·009·010
- FNC-A-013(우선순위 중)은 FNC-A-014 처리 순서 1번이 다시 호출하므로 1단계에 넣었다.

1단계에서 미루는 부분(같은 기능의 나머지는 2·3단계 기능에서 구현)
- 이벤트: FNC-A-028의 이벤트 검사(FNC-A-033·034), FNC-A-025의 캠 이상 이벤트(FNC-A-035) → 2단계. 지도·대시보드의 이벤트 수는 1단계에서 0.
- 실시간 갱신: 알림 SSE(FNC-A-048)·통계 SSE(FNC-C-022) → 2단계. FNC-A-022는 목록 조회·상태 표시까지.
- 라이브 캠: FNC-S-001의 LIVE 분기(FNC-S-007·008) → 2단계. 1단계는 DUMMY만.
- 영상 화면: FNC-S-010의 MJPEG·스냅샷 버퍼(FNC-S-011) → 2단계.
- 회원: 사용자 앱 가입·승인(FNC-U-002·FNC-A-006) → 2단계. 1단계는 관리자 앱 로그인으로 흐름을 확인한다.

## 근거
- 기능 우선순위만으로는 '상'이 63개라 첫 목표로 너무 크고, 서로 의존하는 기능이 섞여 있어 순서가 정해지지 않는다.
- spring ↔ flask 계약(api/analyzer.md)이 맞물리는 지점을 1단계에서 먼저 끝까지 돌려 봐야, 뒤 단계 기능이 같은 흐름 위에 붙는다.

## 영향
- 기능 하나 = 이슈 하나. 이슈 제목 `[FNC-…] 기능명`, 라벨 `type:feature` + `area:common/user/admin/analyzer`, 보드 `단계`·`명세서 ID` 필드를 채운다.
- 2·3단계 이슈의 '먼저 끝나야 하는 이슈'는 기능 본문(후속 동작 제외)에 적힌 FNC ID로만 채웠다. 본문에 적히지 않은 의존은 이슈 관계로 따로 건다.
- 기능을 추가하면 우선순위 기준으로 단계를 정하고, 1단계 흐름에 꼭 필요하면 이 기록의 1단계 목록에 추가한다.
