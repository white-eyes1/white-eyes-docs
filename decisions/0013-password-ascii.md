# 0013. 비밀번호 문자를 ASCII로 제한

- 상태: 채택
- 기록: 2026-10-19
- 관련: conventions.md '입력값 규칙 > 비밀번호', FNC-C-005, sec-001, white-eyes-spring PR #101

## 결정
비밀번호에는 영문·숫자·특수문자(공백을 뺀 ASCII 출력 문자)만 쓸 수 있다. 길이 규칙(8~64자)과 영문·숫자 각 1자 이상 규칙은 그대로 둔다. 회원가입·비밀번호 변경 등 비밀번호를 받는 기능의 입력 검증에서 이 규칙을 지키지 않으면 400으로 거절한다.

## 근거
- bcrypt(FNC-C-005)는 비밀번호를 72바이트까지만 받는다. Spring의 `BCryptPasswordEncoder`는 72바이트를 넘으면 `encode`에서 예외를 던진다. 기존 규칙(8~64자)은 문자 종류를 막지 않아, 한글(UTF-8 3바이트)을 섞은 비밀번호는 72바이트를 넘어 500 오류가 날 수 있었다.
- ASCII는 한 글자가 1바이트라 64자여도 64바이트로 한도 안에 들어온다. 바이트 길이로 제한하는 방식은 같은 글자 수라도 통과 여부가 달라져 사용자에게 설명하기 어렵다.
- 한글 등 유니코드를 허용하려면 72바이트 검사 외에 유니코드 정규화(NFC)도 필요하다. macOS와 Windows가 같은 한글을 다른 바이트로 보낼 수 있어, 정규화하지 않으면 다른 기기에서 로그인이 실패한다.

## 검토한 다른 방법
- 유니코드 허용 + NFC 정규화 + 72바이트 초과 400: 표준 지침(NIST SP 800-63B)이 권하는 방향이지만, 정규화·바이트 검사·안내 문구가 더 필요하고 얻는 강도는 길이(최대 64자)에 비해 작다. 나중에 ASCII에서 유니코드로 넓히는 것은 기존 비밀번호를 깨뜨리지 않으므로 필요해지면 그때 바꾼다.
