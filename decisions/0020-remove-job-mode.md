# 0020. 1회 실행 작업(--job)을 없애고 기준 데이터는 Flyway로, 시연 도구는 tools 모듈로 나눔

- 상태: 채택
- 기록: 2026-11-08
- 관련: FNC-A-012·051·052, loca-001, conventions.md 'DB 계정', package-structure.md, 0004(prod는 코드만), 0014(일부 대체), white-eyes-spring #286·#374·#375·#238

## 맥락
- 행정구역 적재와 시연용 통계 생성·삭제가 관리자 앱의 실행 옵션(`--job=load-regions`, `generate-demo`, `delete-demo`)이었다. 작업 하나를 돌릴 때마다 관리자 앱 전체를 웹 서버 없이 띄웠다.
  - 웹 빈을 하나씩 끄는 `@ConditionalOnWebApplication`이 26개 파일에 퍼졌고, 세션·SSE를 쓰는 기능을 만들 때마다 늘었다.
  - 시연용 코드(약 1,000줄)가 운영용 관리자 앱 이미지에 들어 있었다(프로필로만 막음).
- 사용자 앱 계정의 표 권한은 일회성 컨테이너(`db-grants`)가 관리자 앱 Flyway 뒤에 줬다. dev·prod는 서비스마다 VM이 달라 compose의 실행 순서 제어를 쓸 수 없다(overview.md '서버 환경').

## 결정
1. 작업 모드(`--job`)를 없앤다. `docker compose up`에는 서비스만 뜨고, 일회성 컨테이너를 두지 않는다.
2. 행정구역(FNC-A-012)은 미리 만든 SQL을 저장소에 두고, 관리자 앱이 시작할 때 Flyway 반복 마이그레이션으로 적용한다.
   - SQL은 개발자가 white-eyes-spring `tools` 모듈의 `region-sql` 명령으로 경계 원본에서 만든다. 지역을 바꾸면 SQL을 다시 만들어 PR로 올리고, 배포 때 적용된다.
   - 넣는 지역은 local·dev·prod 모두 같다: 대전 5개 구와 맞닿은 시·군·구 14곳(대전 동·중·서·유성·대덕구, 세종시, 청주시 상당·서원구, 보은군, 옥천군, 공주시, 논산시, 계룡시, 금산군). 읍·면·동 196개. 일반시의 구(청주)·구 없는 시(공주 등)·군이 함께 있어 0014가 시연 지역에 바란 구조 차이도 들어 있다.
3. 사용자 앱 계정의 표 권한은 Flyway의 `afterMigrate`가 매번 준다(새 표도 자동). 표를 바꾸고 권한을 주는 일은 Flyway 전용 계정이 하고, 관리자 앱 실행 계정은 데이터 읽기·쓰기만 가진다.
4. 시연용 통계 생성·삭제(FNC-A-051·052)는 운영 앱 밖의 `tools` 모듈로 옮긴다. `common`에만 의존하고 웹·예약 작업 없이 뜨며, 명령이 끝나면 종료한다. local·dev 프로필이 아니면 실행하지 않는다.
   - local: `./gradlew :tools:bootRun` 또는 `docker compose run --rm tools …`(compose의 `profiles`라 up에는 안 뜸)
   - dev: 관리자 앱과 같은 버전의 tools 이미지를 `docker run --rm`으로 실행
   - prod: tools를 올리지 않는다

## 이유
- PM 결정(2026-11-05~08): 작업 모드는 반드시 없앤다. up에는 서비스만 둔다. 시연 코드는 운영 앱에서 뺀다. 행정구역 데이터는 출처를 표기하고 공개 저장소에 넣는다. 지역은 시험을 많이 한 대전과 그 인접 지역으로 한다.
- 행정구역은 드물게 바뀌고 모든 환경에 똑같이 필요하며 앱이 뜨기 전에 있어야 하므로, 스키마처럼 코드와 함께 버전 관리하는 기준 데이터로 다룬다.
- 시연용 통계는 등록한 구역과 캠 첫 가동 시각에 맞춰 만들어야 해서 미리 만든 데이터(덤프)로는 끊김 없이 이을 수 없다. 집계 규칙(`StatRollupCalculator`, 일별 묶음)을 관리자 앱과 같이 써야 해서 같은 저장소의 Java 모듈로 둔다.
- Flyway는 관리자 앱 프로세스 안에서 DB에 접속해 돌므로 DB가 다른 VM이어도 같다. 권한 부여를 Flyway에 두면 CI(spring #238)와 deploy가 같은 방법을 쓴다.

## 검토한 다른 방법
- 관리자 앱 내장 명령 유지(구현만 고침): 시연 코드가 운영 이미지에 남는다.
- 행정구역을 관리자 앱 내부 API로 적재: 기준 데이터를 덮어쓰는 API가 운영에 항상 열려 있고, 분석 서버와 같은 토큰으로 바꿀 수 있다.
- 일회성 mysql 컨테이너로 SQL 적재·권한 부여: up에 일회성 컨테이너가 남고, VM 환경에서 순서를 맞추기 어렵다.
- 행정구역·시연 생성기를 deploy 저장소의 Python 스크립트로: 경계 합치기(JTS)·집계 규칙을 두 언어로 관리하고 스키마가 바뀌어도 컴파일 오류가 나지 않는다.
- 환경마다 다른 지역(서비스 지역 / 시연 지역 묶음): 환경마다 Flyway 경로 설정을 관리해야 하고, 묶음을 빼면 Flyway 검증이 실패할 수 있다.
- 전국 적재: 읍·면·동 3,559개(원본 약 35MB). 구역 미리보기가 읍·면·동을 모두 도는 구조를 먼저 고쳐야 한다.

## 영향
- 0014 결정 4번의 지역(대전 중구·수원시영통구·김포시)은 이 기록의 지역으로 바뀐다. 경계 원본·출처 표기는 0014 그대로다.
